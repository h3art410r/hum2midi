# Make Anything Musical — Demo Spec

- 版本：0.9（最小端到端 Demo + 旋律语义 A/B）
- 日期：2026-09-16
- 目标：验证用户哼唱能被转成结构化旋律，并由云端文本模型根据 MIDI 语义完成 Funk / Lofi 风格转换。

## Demo 流程

1. 手机浏览器打开单页，按住按钮录制 5–15 秒真实哼唱；支持重录和取消。
2. 用户提交录音，页面说明录音会发送至云端模型处理。
3. 后端必须调用国内可用的云端音频多模态模型，对整段哼唱做整体旋律理解。
4. 服务端对同一真实录音做确定性基频、发声起止和停顿检测，合并成 acoustic canonical MIDI 1.0 MelodyIR。
5. 可运行独立的 `melody_semantic` A/B 层，把测量音高、相对音程和节奏交给云端文本模型判断是否匹配其已有记忆中的常见简谱；只有非常相似时才替换音高。它不改变音符数量、起音、时值或停顿，也不携带歌名、外部曲谱或联网资料；不相似则保留声学测量。
6. 将选定的 canonical MIDI 的音符、时值、速度和乐句结构交给支持结构化输出的云端文本模型，由模型一次性创作完整的 Funk 和 Lofi 风格 MIDI。canonical MIDI 是音乐种子，不是逐音不变的约束；模型可以重写音高、时值、时序、和声、低音、鼓组与段落，但要保留核心动机和乐句顺序。
7. 服务端校验模型输出并将两个风格 MIDI 渲染成 WAV，页面展示两个风格版本。

## 页面与录音

- 一个响应式页面，手机端为主要体验；桌面端显示 16:9 调试画布。
- 录音限制 5–15 秒，显示时长，支持取消、重录、提交。
- 处理过程显示阶段和错误；支持失败重试，不无限等待。
- 录音无效、权限拒绝、旋律未识别时显示明确提示。
- 结果区可展开逐音调试图，按时间和 MIDI 音高显示每个音的起点、时值与乐句边界，便于桌面 16:9 视图核验识别结果。

## 数据与处理

- 录音必须进入真实的云端理解流程；禁止预制音频、mock IR 或 mock 结果伪装成实时转换。
- 首选候选为阿里云百炼 Qwen-Omni 音频理解 API。模型负责云端听音并确认整体旋律；精细音符边界与基频由确定性 YIN/能量检测测量。随后可选的 `melody_semantic` 层只生成可审计的音高假设，再由文本模型读取 canonical MIDI 并整体转换成风格 MIDI，不是把原旋律轨原样保留后再简单追加音轨。语义模型不可用或返回低相似度时必须保留测量 MIDI，并在 job 诊断中记录原因。
- 音频使用 WAV/PCM 传入云 API，密钥与百炼 Workspace ID 仅放服务端环境变量。
- MIDI 1.0 是 canonical 旋律文件；伴随的版本化 MelodyIR JSON 保留音高、起始秒数、时值、力度、置信度、速度和来源，并额外记录测得音高相对整数 MIDI 的音分偏移及距相邻半音决策边界的余量。导出 MIDI 时用标准 pitch bend 保留这部分细微音准，不改变整数音符语义。
- 风格 MIDI 由文本模型一次性生成完整风格多轨，服务端只校验 JSON、音符范围、时值范围和轨道数量，不强制逐音复制 canonical MIDI；WAV 优先由 FluidSynth 加获许可的 SoundFont 渲染，未配置音源时回退到可解释的程序化合成器。渲染过程不加载本地 ML 模型，也不调用音频生成 API。
- 后端使用 Python + FastAPI。任务状态留在进程内存；原始录音、MIDI 和 WAV 结果放在临时目录 `data/demo/`，不加入版本控制；刷新后不保证保留。
- API：`POST /api/generations` 上传音频并创建任务；`GET /api/generations/{id}` 查询状态；`GET /api/generations/{id}/audio/{style}` 播放结果。
- 用户音频会发送到云服务；只使用参与者明确同意的录音，不上传他人或敏感音频。

## 验收

- 真实 5–15 秒录音能成功进入云端理解，生成非空 MIDI IR 与 MIDI 文件。
- 模型生成的两个完整风格 MIDI 及其 WAV 均可在浏览器播放；风格结果应保留 canonical MIDI 的核心动机和乐句顺序，并在节奏、配器和音色上体现 Funk/Lofi 差异。
- Funk / Lofi 在节奏、配器和音色上可区分，同时保留原旋律核心动机与乐句顺序。
- 错误和无旋律情况提示清晰；至少连续完成三次现场流程，无需重启服务。
- 在三段不同难度的真人哼唱上人工试听评估音高/时值识别。当前已对一段真实录音完成云端调用、MIDI 往返、独立音高/起音交叉核验；三段样本的总体验收仍待另外两段真人录音。

## 范围外

- 短视频、账号、社区、支付、作品历史、MIDI/stems 导出、DAW 编辑。
- 自训或本地运行任何音频/音乐模型。
- 生产级安全、扩容和可用性承诺。

## 已确认决策

- 两个风格：Funk、Lofi。
- 录音时长：5–15 秒。
- 云端多模态音频理解即可，不要求模型原生支持音乐生成。
- 输出音频严格由模型生成的风格 MIDI 事件渲染，不在 MIDI 之外自动补鼓点或伴奏；默认优先使用 FluidSynth SoundFont 获得真实乐器质感，程序化合成器只作为可复现的环境回退；模型负责整体风格创作语义，试听音质不代表最终产品音质。
- 不接入 Mureka 等按首计费的音乐转谱/成品生成接口。

## 依据与待验证项

阿里云文档列出 Qwen3.5-Omni HTTP 模型支持音频输入，并给出 OpenAI 兼容接口；音频输入可用 Base64，要求流式调用。其文档也说明 Qwen Audio 可理解音乐、歌声并分析节奏/调性，但通用模型对单段哼唱做逐音符、精确时间戳输出的准确率**尚未被官方能力保证**。真实录音实测表明它会生成等间隔错谱，因此 Demo 用确定性声学测量生成细粒度音符，同时必须由云模型确认整体高低走向；整段 API 失败时不生成结果。

- [Qwen-Omni 音频输入 API](https://help.aliyun.com/zh/model-studio/qwen-omni)
- [Qwen 音频理解能力说明](https://help.aliyun.com/zh/model-studio/audio-language-model)

## 转谱提示与当前限制

转谱请求只包含录音，不传歌名、歌词或预期曲谱，也不要求模型报告歌名。提示模型完整聆听音频并描述整体旋律；细粒度音符由声学测量产生，语义模型只能在高度相似时按简谱记忆修正音高。项目不以模型自报置信度证明转谱正确。

2026-09-15 对用户录音的早期云模型逐音转谱曾出现漏音及音高/节奏不符，因此主流程由确定性声学测量输出细粒度 MIDI，云端 Omni 负责不可跳过的整体走向校验。针对当前真人录音，负责人确认两句、14 音；独立 librosa YIN/pYIN 稳定音高与 IR 为 14/14 一致，独立谐波频谱估计为 13/14 一致，分歧音正处于 MIDI 54/55 取整边界；独立频谱流起音与事件起点最大差 10ms，MIDI 往返保留 14 个事件和时间信息。客观交叉核验支持当前转换结果，但该边界音仍有取整歧义；仍需负责人试听 MIDI 参考确认主观旋律贴合度，且三段真人录音验收尚缺另外两段。更多方法与结果见 `docs/MODEL_REVIEW.md`。
